
<h1 align="center">Sugar-Binding Predictor</h1>

Sugar binding predictor, a deep learning classifier to predict binding between protein and carbohydrate.  

![overview drawio](https://github.com/Jacky233emm/sugar_binding_predictor/assets/91257855/d781ac20-844f-42fe-bf31-033a57e2bebc)

<h2 align="left">Introduction</h2>

This method takes the `.pdb` structure file as input and outputs **1 or 0** to indicate successful or failed binding. Protein–sugar interacting graphs are generated by preprocessing the structure file. The interacting graph and associated structural features are then passed to a deep neural network including:

- **Spherical Message Passing Network (SphereNet)** [Liu et al., 2021] to encode geometric information from atomic coordinates  
- **Principal Neighborhood Aggregation (PNA) layers** [Corso et al., 2020] for graph feature aggregation  
- **Super-node hierarchical graph pooling** [Ying et al., 2019] to summarize fragment-level representations  

The pooled features are processed by fully connected layers and the classifier returns a binary result indicating predicted sugar-binding capability.

![image](https://github.com/Jacky233emm/sugar_binding_predictor/assets/91257855/9d2bb179-db61-4328-8851-bed8abfb9c94)

<h2 align="left">Workflow Overview</h2>

The prediction pipeline consists of two main stages:

```
Protein–carbohydrate complex (.pdb)
|
Preprocessing
↓
Minimum binding-site graph
|
Geometric Graph Neural Network
↓
Binary prediction (binding / non-binding)
```

The preprocessing step converts the structural complex into a **reduced binding-site representation**, keeping only atoms relevant to carbohydrate recognition rather than the full protein structure.

The retained atoms typically include:

- carbohydrate atoms
- interacting amino-acid side-chain functional groups
- interacting backbone atoms
- aromatic residues involved in CH–π interactions

These atoms form a **protein–carbohydrate interaction graph** used as input to the neural network.

<h2 align="left">Model Scripts</h2>

The main scripts used in the prediction workflow are located in the **model** directory.

### `run_predict.py`

Main entry script for prediction.

Responsibilities:

- parses command line arguments
- performs preprocessing (if raw `.pdb` files are provided)
- loads pretrained models
- runs prediction
- writes prediction results

Supported input types:

- single complex `.pdb`
- list of `.pdb` files
- preprocessed binding-site text files

---

### `pdb_n2n_input.py`

Structure preprocessing module.

This script converts a protein–carbohydrate complex `.pdb` file into the **minimum binding-site representation** used by the model.

Main tasks:

1. read atom records from the PDB file  
2. identify carbohydrate ligands  
3. detect nearby interacting protein atoms  
4. encode atom types and fragment identities  
5. build graph edges and interaction features  
6. write a processed file `*_elicit_info.txt`

The resulting file contains the atom features, coordinates, and graph structure required by the neural network.

---

### `sugar_binding_predictor.py`

Defines the deep learning model architecture.

The model includes:

- SphereNet-based geometric message passing
- PNA graph aggregation layers
- hierarchical graph pooling
- fully connected layers for binary classification

---

### `spherenet_M.py`

Modified implementation of **SphereNet**, used to incorporate 3D geometric information such as:

- interatomic distances  
- bond angles  
- torsion angles  

into the graph message passing framework.

---

### `geometric_computing.py`

Utility functions used for geometric calculations during graph construction and message passing.

---

### `features.py`

Functions for constructing atom and fragment features used as model input.

---

### `measure_CH_pi.py`

Detects **CH–π interactions** between carbohydrates and aromatic residues, which can be included as additional interaction information.

<h2 align="left">Preprocessing Workflow</h2>

The preprocessing step converts the structural complex into the graph representation used by the model.

Steps:

1. **Read the complex structure**

   The script loads `ATOM` and `HETATM` records from the input `.pdb`.

2. **Identify carbohydrate ligand**

   Known carbohydrate residues are detected and selected as ligand nodes.

3. **Detect interacting residues**

   Protein atoms near the carbohydrate are selected as the local interaction environment.

4. **Construct reduced binding site**

   Only atoms involved in potential interactions are retained.

5. **Encode atom and fragment types**

   Atom and fragment types are mapped using:

   ```atom_type_old.txt```
   ```sugar_fragment_type.txt```

7. **Build interaction graph**

   Nodes represent atoms and edges represent spatial interactions.

8. **Export model input**

   The processed data is written as:

   ```*_elicit_info.txt```

This file is the direct input for the prediction model.

 <h2 align="left">Running</h2>

Simply run by: 
```sh
cd ./model/
python run_predict.py
```
Running option: 

`--complex_pdb` : Load complex .pdb file.

`--file_path` : File path of input file. 

`--with_label` : Label `1` or `0` of input complex, if unknown set `None`. 

`--complex_list` : Load list of complex .pdb file, label can be added after the file name seperated by a tab. 

`--model` : Model parameter for prediction, there are `well-trained` and `general` two options, in default both of them would be used.
